# 全息风格星球

一颗会发光的星球，画在浏览器里。你可以拖动旋转视角，用滚轮或双指缩放，也可以暂停自转、重置视角。

**这是屏幕上的三维视觉效果，不是物理全息投影。** 它不会出现在空气里。

这一版只有一个视角，用来认识场景和交互。不切换星球，也不做金字塔四画面。

## 怎么运行

在项目目录打开终端（需要已安装 Node.js，本环境是 v22.23.4）：

```bash
npm install
npm run dev
```

浏览器打开 [http://127.0.0.1:43123](http://127.0.0.1:43123) 。

不要直接双击 `index.html`。浏览器会拦住这种打开方式里的模块导入，画面出不来。

生产构建：

```bash
npm run build
npm run preview
```

`npm run build` 生成 `dist/`。`npm run preview` 在本项目里打开 [http://127.0.0.1:43124](http://127.0.0.1:43124) 。

停掉开发服务器用 `Ctrl+C`。

依赖版本写死在 `package.json` 里，锁文件是 `package-lock.json`：

- `three` 0.187.0
- `vite` 8.3.8

## 五个概念

**1. 场景、相机、渲染器。** 场景 `scene` 是舞台，星球和星星都放进去。相机决定你从哪儿看，现在数组 `cameras` 里只有一台，放在星球前上方，看向原点。渲染器 `renderer` 把舞台画进 `index.html` 里的 `<canvas>`。浏览器没有 WebGL 时，不会硬画，页面改成显示「无法显示三维画面」。

**2. 球体与材质。** 星球是 `SphereGeometry`，半径是 1。表面颜色来自 `createSurfaceTexture()`：用画布画出海洋、陆块和经纬线，再贴到球上。没有外部图片文件。表面是不透明的，这样后面的光晕只会露在轮廓外面。

**3. 光照与辉光。** `createLights()` 放了三盏灯：半球光托住暗部，平行光分出亮面，点光源从侧后方补青色。表面用的 `MeshPhongMaterial` 会吃到这些灯。轮廓上那圈更亮的边来自外面两层壳，着色器按视角算亮度（菲涅尔）：越靠近轮廓越亮。所以它看起来像在发光，但光只存在于屏幕像素里。

**4. 控制。** `OrbitControls` 把拖动变成绕星球转动，把滚轮和双指变成拉近拉远。`minDistance` 和 `maxDistance` 限制最近和最远，避免钻进星球或缩到看不见。平移是关掉的，所以目标点一直在星球中心。`暂停自转` 只停星球自己转，视角还能拖。`重置视角` 回到刚打开时的机位，不把自转倒回去。

**5. 动画。** `animate()` 用 `requestAnimationFrame` 每一帧跑一次。自转角度是 `spinSpeed × 这一帧的秒数`，刷新率不同，快慢仍接近。然后 `controls.update()` 把阻尼算完，`renderFrame()` 清一次屏，再交给 `renderView()` 画当前这一块视口。

## 三个小练习

都在 `src/main.js` 最上面。改完保存，开发服务器会刷新页面。

1. 把 `spinSpeed` 从 `0.18` 改成 `0.6`，看自转变快。再改回去。
2. 把 `glowColor` 从 `0x5eead4` 改成 `0x7aa2ff`（偏蓝）或 `0xc8ff6a`（偏黄绿），看灯、亮边和环的颜色一起变。颜色是 `0xRRGGBB`。
3. 把 `minDistance` 改成 `3`，把 `maxDistance` 改成 `5`，再用滚轮缩放，感受最近和最远。不要把 `minDistance` 设得比 `1.6` 还小，相机会钻进星球。两个数要保持最小小于最大。

## 后续实物路线

你要做的是桌上的互动展示，不只是电脑里的画面。常见做法是：一块屏幕播放图像，屏幕上方或下方放一个透明、能反光的金字塔。人看到的是屏幕画面映在透明面上的反光，物体好像浮在金字塔中间。这叫佩珀尔幻象（Pepper's ghost），是舞台上用了很久的反射错觉。

它不是自由空间里的真全息。空气中没有被投出来的立体光点。换到没有这几片反射面的方向，就看不到这颗星球。

金字塔的底边、高度、每一面的角度，都得按你手头那块屏幕来算。屏幕多大、横竖、边框多厚，这些数都会变。现在还不知道用哪块屏幕，所以这里不写尺寸，不写材料清单，也不写价格。

这一版故意只有一个视角。`src/main.js` 里已经把「画一个视角」单独放好了：

- `createCameras()` 目前只创建一台主相机。以后再加三台，不要重写星球。
- `syncCameras()` 会抄主相机的距离和俯仰，给额外相机加上 90°、180°、270° 的水平角。这样四面看到的是同一姿态，而不是四颗各转各的星球。
- `layoutViewports()` 和 `renderView()` 负责把某台相机画进屏幕上的一块矩形。现在这块矩形就是整屏。
- 相机朝向（看到星球的哪一侧）和这块画面在屏幕上的旋转，是两件事。反射会把画面翻一下，转多少才能对人正立，要等屏幕放在金字塔上方还是下方确定后再算。

切换不同星球、接硬件、串口和语音，都不在这一步。

## 本环境实测

Node.js v22.23.4。下面几条都实际跑过：

```bash
npm install
npm run build
npm run dev
npm run preview
```

- `npm install` 成功，并写出 `package-lock.json`。
- `npm run build` 成功，文件在 `dist/`。构建没有报错。
- 开发页：[http://127.0.0.1:43123](http://127.0.0.1:43123)
- 生产预览：[http://127.0.0.1:43124](http://127.0.0.1:43124)

用无头 Chrome（软件 WebGL）打开过开发页和生产预览：

- 两个页面的控制台都没有 JavaScript 错误。
- 拖动后视角变了（光环的倾斜跟着变）。
- 滚轮缩小后星球变小；再点「重置视角」，机位回到打开时的角度。
- 连续放大不会钻进星球，连续缩小后星球仍留在画面中间。
- 「暂停自转」会变成「继续自转」，星球自己停转。
- 用触摸事件模拟双指张开，星球变大。没有在真机上用手指捏合。
- 关掉 WebGL 后，页面显示「无法显示三维画面」。
- 390×844 的窄窗口里，说明和两个按钮都在，星球不被挡住。
