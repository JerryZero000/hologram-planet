# 全息风格星球

一颗会发光的星球，画在浏览器里。你可以拖动旋转视角，用滚轮或双指缩放，也可以暂停自转、重置视角。页面上能在「单视角」和「四面预览」之间切换。

**这是屏幕上的三维视觉效果，不是物理全息投影。** 它不会出现在空气里。

不切换星球，也不接硬件、串口或语音。

## 怎么运行

在项目目录打开终端（需要已安装 Node.js，本环境是 v22.23.4）：

```bash
npm install
npm run dev
```

浏览器打开 [http://127.0.0.1:43123](http://127.0.0.1:43123) 。

不要直接双击 `index.html`。浏览器会拦住这种打开方式里的模块导入，画面出不来。

生产构建：

```bash
npm run build
npm run preview
```

`npm run build` 生成 `dist/`。`npm run preview` 在本项目里打开 [http://127.0.0.1:43124](http://127.0.0.1:43124) 。

停掉开发服务器用 `Ctrl+C`。

依赖版本写死在 `package.json` 里，锁文件是 `package-lock.json`：

- `three` 0.187.0
- `vite` 8.3.8

## 入口文件

| 路径 | 作用 |
| --- | --- |
| `index.html` | 页面、中文说明、WebGL 不可用时的提示 |
| `src/main.js` | 场景、星球、光照、控制、动画 |

| `vite.config.js` | 开发端口 `43123`，预览端口 `43124` |

三维逻辑都在 `src/main.js`，按五个小节往下读即可。

## 五个概念

**1. 场景、相机、渲染器。** 场景 `scene` 是舞台，星球和星星都放进去。相机决定你从哪儿看。`cameras` 里有四台，都看向原点。单视角只用第一台；四面预览四台一起用。渲染器 `renderer` 把舞台画进 `index.html` 里的 `<canvas>`。浏览器没有 WebGL 时，不会硬画，页面改成显示「无法显示三维画面」。

**2. 球体与材质。** 星球是 `SphereGeometry`，半径是 1。表面颜色来自 `createSurfaceTexture()`：用画布画出海洋、陆块和经纬线，再贴到球上。没有外部图片文件。表面是不透明的，这样后面的光晕只会露在轮廓外面。

**3. 光照与辉光。** `createLights()` 放了三盏灯：半球光托住暗部，平行光分出亮面，点光源从侧后方补青色。表面用的 `MeshPhongMaterial` 会吃到这些灯。轮廓上那圈更亮的边来自外面两层壳，着色器按视角算亮度（菲涅尔）：越靠近轮廓越亮。所以它看起来像在发光，但光只存在于屏幕像素里。

**4. 控制。** `OrbitControls` 只拖主相机：拖动是绕星球转，滚轮和双指是拉近拉远。`minDistance` 和 `maxDistance` 限制最近和最远，避免钻进星球或缩到看不见。平移是关掉的，所以目标点一直在星球中心。四面预览时，另外三台相机跟着主相机走，不会各转各的。`暂停自转` 只停星球自己转，视角还能拖。`重置视角` 回到刚打开时的机位，不把自转倒回去。

**5. 动画。** `animate()` 用 `requestAnimationFrame` 每一帧跑一次。自转角度是 `spinSpeed × 这一帧的秒数`，刷新率不同，快慢仍接近。然后 `controls.update()` 把阻尼算完，`renderFrame()` 清一次屏，再交给 `renderView()` 画当前这一块视口。

## 三个小练习

都在 `src/main.js` 最上面。改完保存，开发服务器会刷新页面。

1. 把 `spinSpeed` 从 `0.18` 改成 `0.6`，看自转变快。再改回去。
2. 把 `glowColor` 从 `0x5eead4` 改成 `0x7aa2ff`（偏蓝）或 `0xc8ff6a`（偏黄绿），看灯、亮边和环的颜色一起变。颜色是 `0xRRGGBB`。
3. 把 `minDistance` 改成 `3`，把 `maxDistance` 改成 `5`，再用滚轮缩放，感受最近和最远。不要把 `minDistance` 设得比 `1.6` 还小，相机会钻进星球。两个数要保持最小小于最大。

## 四面预览

点「四面预览」或「单视角」切换。打开页面时默认是四面预览。这个选择记在当前标签页里，刷新还在；换一个标签页会回到默认。

四面预览是一个十字：上、下、左、右各一块正方形，中间和四个角是空的。假设你的手机或平板**屏幕朝上**，透明金字塔**放在屏幕上面**（屏幕在金字塔下面）。人从侧面看的是塑料面上的反光，不是空气里的光。

四块画的是**同一颗**星球的同一个姿态。`syncCameras()` 抄主相机的距离和俯仰，再把水平角加上 0°、90°、180°、270°。拖动或缩放时，四面一起动。

相机朝哪边，和这块画面在屏幕上转多少，是两件事。转画面的数在 `src/main.js` 顶部的 `PYRAMID_VIEWS`，字段叫 `rollDegrees`（正数是逆时针）。现在的一组是让每块的「上」朝向屏幕中心，给「屏幕在下」用。如果以后把屏幕改到金字塔上方，把每个 `rollDegrees` 改成相反数：`90` 和 `-90` 对调，`0` 和 `180` 不用改。

十字有多大，是按当前窗口算的，用来在屏幕上预览。这不是金字塔的边长。屏幕多大还不知道，所以这里不写尺寸，不写材料，也不写价格。

## 后续实物路线

你要做的是桌上的互动展示，不只是电脑里的画面。常见做法是：一块屏幕播放图像，屏幕上方或下方放一个透明、能反光的金字塔。人看到的是屏幕画面映在透明面上的反光，物体好像浮在金字塔中间。这叫佩珀尔幻象（Pepper's ghost），是舞台上用了很久的反射错觉。

它不是自由空间里的真全息。空气中没有被投出来的立体光点。换到没有这几片反射面的方向，就看不到这颗星球。

金字塔的底边、高度、每一面的角度，都得按你手头那块屏幕来算。屏幕多大、横竖、边框多厚，这些数都会变。现在还不知道用哪块屏幕，所以这里不写尺寸，不写材料清单，也不写价格。

这一版只在屏幕上排出四块画面，方便你先看反射用的图。`createCameras()`、`syncCameras()`、`layoutViewports()`、`renderView()` 还是那四个入口，星球本身没有为了四面重写。切换不同星球、接硬件、串口和语音，都不在这一步。

## 本环境实测

Node.js v22.23.4。下面几条都实际跑过：

```bash
npm install
npm run build
npm run dev
npm run preview
```

- `npm install` 成功。
- `npm run build` 成功，文件在 `dist/`，构建没有报错。
- 开发页：[http://127.0.0.1:43123](http://127.0.0.1:43123)
- 生产预览：[http://127.0.0.1:43124](http://127.0.0.1:43124)

用无头 Chrome（软件 WebGL）打开过开发页和生产预览，两边结果一样：

- 控制台没有 JavaScript 错误。
- 打开就是四面预览：上、下、左、右各有一颗星球，正中间是空的。
- 拖动后四块都变了，中间还是空的。滚轮缩小后四块一起变小。点「重置视角」回到拖动前的机位。
- 「暂停自转」变成「继续自转」后，画面基本停住。在单视角里再点「暂停自转」（这时按钮写着「继续自转」），星球又转起来。
- 「单视角」和「四面预览」都能切过去。单视角是一整屏一颗星球。
- 切回四面预览再刷新，还停在四面预览。
- 390×844 的窗口里，十字在中间，说明在上面，按钮在下面，都点得到，没有压住四块画面。
- 关掉 WebGL 后，页面显示「无法显示三维画面」。

没有在真机上用手指捏合，也没有拿实物金字塔对着屏幕看。`rollDegrees` 是按「每块的上方朝向屏幕中心」定的。
